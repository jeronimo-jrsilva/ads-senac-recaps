A quinta aula de **Banco de Dados** com o Professor Alexandre abordou em profundidade a resolução de relacionamentos Muitos-para-Muitos ($N:M$) no modelo relacional, a eliminação de redundâncias e a criação de tabelas associativas para gerenciar notas e vínculos entre alunos e disciplinas.

---

## 1. O Problema da Redundância e Relacionamentos $N:M$
O Professor Alexandre demonstrou o que acontece quando tentamos armazenar notas de alunos diretamente na tabela de `Aluno` ou na tabela de `Disciplina`:
- Um aluno cursa várias disciplinas, e uma disciplina possui vários alunos matriculados ($N:M$).
- Se colocarmos os dados na mesma tabela, haverá duplicação descontrolada de nomes, códigos e cadastros a cada nova nota lançada.

---

## 2. Implementação da Tabela Associativa
A solução formal no modelo relacional é decompor a relação $N:M$ em dois relacionamentos $1:N$, introduzindo uma terceira tabela intermediária (tabela associativa):

- **Tabela `Aluno`:** Armazena apenas dados cadastrais únicos do estudante (`id_aluno`, `nome`, `matricula`).
- **Tabela `Disciplina`:** Armazena dados cadastrais da matéria (`id_disciplina`, `nome_disciplina`, `carga_horaria`).
- **Tabela `Historico_Notas` (Associativa):** Contém as chaves estrangeiras (`id_aluno`, `id_disciplina`) e os atributos específicos do relacionamento (por exemplo, `nota_1`, `nota_2`, `frequencia`).

```sql
-- Exemplo de estrutura relacional associativa discutida em sala
CREATE TABLE Aluno (
    id_aluno INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);

CREATE TABLE Disciplina (
    id_disciplina INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);

CREATE TABLE Historico_Notas (
    id_aluno INT,
    id_disciplina INT,
    nota_1 DECIMAL(4,2),
    nota_2 DECIMAL(4,2),
    PRIMARY KEY (id_aluno, id_disciplina),
    FOREIGN KEY (id_aluno) REFERENCES Aluno(id_aluno),
    FOREIGN KEY (id_disciplina) REFERENCES Disciplina(id_disciplina)
);
```

- Com essa modelagem, o código do aluno e da disciplina são únicos em suas respectivas tabelas, garantindo integridade referencial e eliminando duplicações no banco de dados.
