A segunda aula de **Banco de Dados Relacional** com o Professor Alexandre conectou a modelagem de dados às metodologias formais da **Engenharia de Software**, estabelecendo o rito que antecede a digitação de scripts SQL na máquina.

---

## 1. O Rito da Engenharia de Software Aplicado a Dados
O Professor Alexandre frisou que o desenvolvimento profissional de software jamais salta diretamente da fala do cliente para a linha de comando:
- **O Erro Amador:** Tentar criar tabelas no banco de dados imediatamente após uma conversa inicial com o usuário.
- **O Rito Profissional:** Respeitar o ciclo de vida da engenharia de dados:
  1. *Levantamento e Análise de Requisitos:* Entender quais dados são essenciais e quais são descartáveis.
  2. *Modelagem Conceitual:* Construção do Diagrama Entidade-Relacionamento (DER).
  3. *Projeto Lógico:* Normalização e conversão de entidades em tabelas e chaves (PK e FK).
  4. *Implementação Física:* Escrita do código DDL (Data Definition Language) no SGBD.
  5. *Testes, Validação e Manutenção Contínua.*

---

## 2. A Camada Conceitual vs. A Camada Lógica
Foi detalhada a separação de abstrações:
- **Modelo Conceitual (Independente de Tecnologia):** Focado no negócio do cliente. Modela quem são as entidades do mundo real (ex: `Cliente`, `Pedido`, `Produto`) e como elas se relacionam (1:1, 1:N, N:N). Não se preocupa se o banco será PostgreSQL, MySQL ou Oracle.
- **Modelo Lógico (Dependente do Paradigma):** Adequação ao modelo relacional. Aqui surgem as regras de integridade referencial, tipos de dados primitivos (`VARCHAR`, `INT`, `DECIMAL`) e a resolução de relacionamentos N:N através de tabelas associativas intermediárias.

---

## 3. Preparação para a Prática em Laboratório
O docente concluiu alinhando as expectativas para os próximos encontros: com a base conceitual de Engenharia de Software e normalização concluída, a turma iniciará a prática direta de criação e manipulação em bancos relacionais via terminal e SGBDs visuais.

## Glossário
- **SGBD (Sistema de Gerenciamento de Banco de Dados)**: Software responsável pelo armazenamento, integridade, controle de concorrência e recuperação de bases de dados relacionais.
- **DER (Diagrama Entidade-Relacionamento)**: Representação gráfica abstrata das entidades de um domínio e seus relacionamentos mútuos.
- **Chave Primária (Primary Key - PK)**: Atributo ou conjunto de atributos que identifica de forma unívoca cada registro dentro de uma tabela relacional.
- **Chave Estrangeira (Foreign Key - FK)**: Campo que estabelece um elo de integridade referencial com a chave primária de outra tabela.
